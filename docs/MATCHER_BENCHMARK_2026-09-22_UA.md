# Локальна перевірка matcher на записах борту — 2026-09-22

Поточний matcher прочитав усі шість скопійованих маршрутів і точно зіставив усі
2583 кадри з їхніми власними індексами. Це контроль читання та алгоритму на
власних даних, а не вимірювання точності незалежного повторного проходу.
Для 11 із 13 окремих stop-frame знімків глобальний пошук обрав інший індекс,
ніж історичний matcher із накопиченим станом. Без розмітки невідомо, який
результат відповідає фізичному місцю.

## Дані й відтворення

- Джерело: [інвентаризація борту](BOARD_RECORDING_INVENTORY_2026-09-22_UA.md).
  Перед запуском повторно перевірено SHA-256 і розміри всіх 19 локальних файлів.
  Борт для цієї перевірки не використовувався.
- WSL2 Linux x86_64, Intel Core i5-10300H, GCC 13.3.0, Ninja,
  Release `-O3 -DNDEBUG`; усі сім camera/output build flags OFF.
- Production core — база `3cae825`; змінені лише окремий діагностичний executable,
  його реєстрація/тести, скрипт звіту та документація. Алгоритм matcher незмінений.
- Локальні результати: `artifacts/matcher-benchmark-20260922/run1/summary.json`,
  31 JSONL із сирими вимірами та 18 логів наявних artifact-check команд.
  Summary містить SHA-256 executable-файлів, вихідного коду інструментів, даних,
  session summary, CMake cache, compile commands і фактичні параметри.
  Source HEAD позначає базу; новий інструмент на момент виміру ще не був закомічений.

```bash
bash scripts/test-software.sh artifacts/config-validation-20260921/clean-build
python3 scripts/benchmark-recorded-routes.py \
  --build-dir artifacts/config-validation-20260921/clean-build/Release \
  --inventory artifacts/board-inventory-20260922 \
  --output-dir artifacts/matcher-benchmark-repeat
```

Скрипт призначений для Linux/WSL. Output directory має бути новою. Дані лишаються
локальними в ignored `artifacts/`; для повторення на іншому ПК потрібні ці файли.

## Метод вимірювання

`gray8_matcher_benchmark` викликає фактичний `Gray8RouteMatcher::match`.
Один повний прогін прогріває кеші; наступні три вимірюються. Кожен прогін створює
новий matcher, тому попередній маршрутний стан не переноситься. Усі результати
трьох повторів збіглися; скрипт перевіряє індекси, confidence, valid і top candidates.

Окремо вимірюються конструктор із копією маршруту/побудовою edge cache, перший
пошук і решта пошуків. Таймер охоплює тільки виклик `match`: читання файлів,
копіювання вхідних кадрів, серіалізація та копіювання діагностичних результатів
поза цим інтервалом. Перший запит виключений із percentile-статистики; percentiles
обчислено методом nearest rank. «Перший» означає порожній стан відстеження,
а не холодний CPU cache.

Кадри подаються послідовно без очікування їхніх timestamps; це не перевірка
freshness, endpoint/dwell, втрат кадрів або повного live pipeline. Напрямок/зсув,
directional bias, initial progress restriction та додаткові probe/ROI виклики
вимкнені. Для self-послідовностей minimum confidence = 0.99, top-N = 0;
scale refinement має radius 1 і штатні 24 масштаби. Радіус 30 узято зі збережених
логів, інші параметри не відтворюють повну історичну конфігурацію.

Це desktop WSL timings без CPU pinning/frequency control; RSS не вимірювався.
З цих чисел не можна вивести FPS Raspberry Pi або всього pipeline.

## Контроль вмісту маршрутів

Усі 2583 self-запити в кожному з трьох режимів повернули власний індекс і confidence 1.
Наявні `--self-match-route` та `--perturb-route` пройшли для всіх шести маршрутів.
Остання команда застосовує brightness +8, alternating noise ±3 та horizontal
shift 1 px із minimum confidence 0.90. Її `passed` перевіряє valid/confidence та
відхилення malformed payload; правильний індекс для зміненого кадру ця команда
не перевіряє. Кількість shift-direction matches також не входить у її `passed`.

Наявний `--route-distinctiveness` із типовими порогами показав:

| Маршрут | Близьких до іншого кадру, MAD ≤ 2/255 | Quality pass |
|---|---:|---|
| 20260708T174000Z | 11 / 300 | так |
| 20260709T151301Z | 9 / 300 | так |
| 20260709T161017Z | 0 / 600 | так |
| 20260710T154326Z | 183 / 183 | ні |
| 20260710T155821Z | 4 / 600 | так |
| 20260712T164651Z | 9 / 600 | так |

Точних дублікатів і low-texture entries за штатним range threshold немає.
Для маршруту `20260710T154326Z` середній nearest MAD = 1.33434 рівня Gray8;
він не проходить наявну quality policy. До пошуку найближчого входять сусідні
в часі кадри, тому це ще не доказ плутанини між віддаленими місцями маршруту.

## Окремі stop-frame знімки

Кожний PGM прив'язано до маршруту через `route=` у start і
`endpoint_stop_frame_path=` у done **того самого log-файлу**. Індекс у назві
знімка не використовується як ground truth. `20260710*` належать маршруту
`20260710T155821Z`, решта — `20260712T164651Z`.

Для кожного знімка виконано незалежний глобальний пошук без попереднього стану,
без scale refinement, top-N = 5. Minimum confidence = 0 для діагностики,
тому `valid=true` тут не є критерієм успішного розпізнавання. Timestamps та id

ймовірність, а `1 − normalized MAD`.

## Конструктивні наступні кроки

1. Окремо профілювати scale refinement на незалежних кадрах. На self-навантаженні
   воно дороге навіть за нульової початкової помилки; перевірити можливість
   раннього завершення з доказом збереження вибору кандидата/нічиїх і directional bias.
   Не вимикати refinement у production лише на підставі self-тесту.
2. Виміряти пам'ять/ініціалізацію edge cache перед зміною його побудови.
   Конструктор зараз створює cache навіть без викликів edge diagnostics;
   самі payloads для 600×160×100 — 9,600,000 додаткових байтів за кодом,
   не виміряний RSS. Якщо робити cache лінивим, зберегти негайну валідацію
   malformed route у конструкторі.
3. Для якості розпізнавання потрібні повний незалежний прохід, timestamps,
   ground truth і off-route negatives. Додати аналіз конкурентів поза локальним
   часовим вікном. Не добирати confidence/gap thresholds за цими 13 кадрами.

## Перевірка нового інструмента

WSL Debug і Release: **53/53 CTest**; readiness log tests: **15/15**;
benchmark helper tests: **5/5**. `BUILD_TESTING=OFF`: нуль зареєстрованих тестів.
Новий C++ self-test перевіряє точні/дубльовані кадри, порядок нічиїх, повторні
прогони та стрибок за межі локального вікна. Перевірки не залежать від `assert`
і залишаються активними в Release. Python tests захищають log-based binding,
відхилення неоднозначних/неповних записів і percentile convention.

Graphify оновлено. GitNexus використано для навігації/review, але його FTS та
повнота call graph обмежені; висновки вище ґрунтуються на коді й виконанні.
Pi/MSVC/live pipeline та hardware acceptance цим кроком не оновлені.
